# مدیریت شرکت پرستاری در منزل — نسخه‌ی 0.12

برنامه‌ی تحت‌وب فارسی (بدون نیاز به سرور). همه‌ی اطلاعات در **حافظه‌ی مرورگر (localStorage)** ذخیره می‌شود.

## ساختار پروژه

```
src/index.template.html   قالب صفحه (سربرگ و بدنه‌ی HTML)
src/css/style.css         همه‌ی استایل‌ها
src/js/NN-*.js            ماژول‌ها (ترتیب شماره مهم است)
src/index.dev.html        نسخه‌ی توسعه: ماژول‌ها را جدا بارگذاری می‌کند
build.py / build.js       ساخت فایل نهایی (یکی از دو تا کافی است)
docs/index.html           خروجی ساخته‌شده؛ همین برای انتشار آنلاین استفاده می‌شود
dist/nursing-app-X.html   همان خروجی با شماره‌ی نسخه در نام
firebase.json             تنظیم Firebase Hosting (پوشه‌ی docs)
```

## ویرایش و ساخت

1. فایل ماژول مربوط را ویرایش کنید.
2. برای آزمایش سریع بدون ساخت: `src/index.dev.html` را در مرورگر باز کنید.
3. برای ساخت فایل نهایی: `python3 build.py` (یا `node build.js`). خروجی در `docs/index.html` و `dist/` ساخته می‌شود.

## انتشار آنلاین

### GitHub Pages
1. در GitHub یک مخزن (repository) بسازید و همه‌ی پروژه را در آن آپلود/Push کنید.
2. مخزن ← Settings ← Pages ← Source: **Deploy from a branch**، شاخه‌ی `main` و پوشه‌ی **/docs** ← Save.
3. بعد از چند دقیقه آدرس `https://USERNAME.github.io/REPO/` فعال می‌شود.
4. هر بار بعد از `build.py` فایل `docs/index.html` را دوباره Push کنید.

### Firebase Hosting
1. یک بار: `npm install -g firebase-tools` و بعد `firebase login`
2. در کنسول Firebase یک پروژه بسازید. فایل `.firebaserc.example` را به `.firebaserc` تغییر نام دهید و شناسه‌ی پروژه را بنویسید (یا `firebase use --add` بزنید).
3. در پوشه‌ی پروژه: `firebase deploy --only hosting`
4. آدرس `https://PROJECT-ID.web.app` ساخته می‌شود.

## نکته‌های مهم قبل از آنلاین کردن

- **اطلاعات به سرور نمی‌رود.** GitHub/Firebase فقط خود برنامه را نشان می‌دهند. اطلاعات هر کاربر روی مرورگر خودش می‌ماند و روی آدرس جدید در ابتدا **خالی** است.
- **انتقال اطلاعات فعلی:** در نسخه‌ی قدیمی «⬇ بکاپ» بگیرید، در آدرس جدید «⬆ بازیابی» را بزنید.
- **ورود با رمز فقط یک قفل ظاهری است:** چون همه‌چیز سمت مرورگر است، کسی که به همان مرورگر/کامپیوتر دسترسی کامل دارد می‌تواند آن را دور بزند. برای امنیت واقعی و کار چندنفره از چند دستگاه، مرحله‌ی بعد اتصال به Firebase Authentication و Firestore است (قوانین دسترسی در سرور).
- اطلاعات بیماران حساس است؛ تا قبل از اتصال به سرور، آدرس عمومی را به اطلاعات واقعی گره نزنید و بکاپ‌ها را امن نگه دارید.
- بکاپ منظم بگیرید (تب «ذخیره‌سازی» در تنظیمات وضعیت بکاپ و فضا را نشان می‌دهد).
